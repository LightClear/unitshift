# UNITSHIFT — 单位跃迁
## 游戏设计文档（Game Design Document）

**文档版本：** V1.0  
**开发代号：** UNITSHIFT  
**游戏类型：** 物理解谜 / 系统型解谜 / 创意实验  
**核心卖点：** 修改物体的物理量，让玩家通过重写现实规则解决谜题  
**目标平台：** PC 优先，Steam 为首发平台候选  
**目标玩家：** 喜欢《Baba Is You》《Portal》《The Witness》等需要观察、推理与实验的解谜玩家  
**开发状态：** 概念与设计阶段，具体玩法、物理规则和关卡尚待原型验证

---

# 一、项目概述

## 1.1 游戏简介

UNITSHIFT 是一款以物理量与计量单位修改为核心机制的第三人称斜视角 3D 解谜游戏。

在游戏世界中，物体并不只有固定的重量、温度、体积与材质。玩家可以使用一种特殊的修改能力，改变物体的物理量，使其获得全新的性质，并与环境中的其他物体、机关和自然现象产生互动。

一块普通的石头，可以被修改为极轻的物体，方便搬运；一个物体可以被赋予高温，成为热源；一个装置可以被赋予电压，成为电力系统的一部分；一个物体也可以改变弹性，在受到撞击时像史莱姆一样弹跳。

玩家需要观察环境、分析目标、修改物体、验证结果，并利用不同物理机制之间的关系寻找通关方法。

**游戏的核心不是寻找唯一的正确道具，而是理解世界的规则，并通过修改规则创造解决问题的方法。**

## 1.2 核心体验目标

游戏希望为玩家提供以下体验：

1. **理解规则：** 玩家能够通过观察与实验，逐渐理解物理量如何影响物体。
2. **主动实验：** 玩家可以尝试不同的参数和单位，而不只是按照提示使用固定道具。
3. **推导结果：** 修改前能够提出假设，修改后能够解释结果。
4. **组合机制：** 一个物体的变化可以影响另一个物体，进而改变整个环境。
5. **发现解法：** 玩家可以发现设计者预期之外、但符合游戏规则的解决方案。

## 1.3 设计支柱

| 设计支柱 | 设计要求 |
|---|---|
| 规则可预测 | 相同条件下，相同修改应当产生一致结果 |
| 修改有意义 | 每种可修改的物理量都必须对应明确的玩法用途 |
| 机制可组合 | 物理量之间可以形成因果链，而非孤立的机关开关 |
| 信息可读 | 玩家能理解物体当前属性、修改结果和失败原因 |
| 关卡有多解空间 | 鼓励实验，但不要求每个谜题都必须多解 |
| 内容可扩展 | 新物理量能够复用既有交互系统，降低后续制作成本 |

## 1.4 产品定位

UNITSHIFT 不以高精度物理模拟为首要目标，而是以**可理解、可推理、可组合的物理规则**为核心。

现实物理是灵感来源，但游戏可以对现实进行适度抽象。例如，玩家将一块石头的质量改为极低后，石头不会自动变成液体；质量变化只影响质量相关的规则。若要改变形态、相态或材质，需要由独立规则决定。

这种设计可以避免玩家混淆“物理量改变”和“单位换算”，也能使关卡更加稳定。

# 二、世界观与叙事方向

## 2.1 世界观概念

建议将游戏设定在一个由物理规律维持的实验世界中。

世界中的每个物体都具有可读取的属性。正常情况下，这些属性决定物体如何运动、受力、传热、发光和与环境交互。

玩家获得了一种特殊能力：读取并修改物体的物理参数。

随着游戏推进，玩家逐渐发现，世界中原本被认为不可改变的规律，其实只是可以被编辑的规则集合。

## 2.2 叙事原则

叙事应当服务于玩法，而不是压过解谜本身。

建议采用环境叙事为主、简短文字为辅的方式：

- 通过实验室、机械设施、废弃装置等场景呈现世界背景。
- 通过异常物体与不完整的实验记录逐步解释修改能力的来源。
- 通过关卡结构让玩家感受到自己正在理解更深层的世界规则。
- 尽量避免大量长篇对话打断玩家的实验节奏。

## 2.3 首发版本的叙事范围

首发版本不必设计复杂的角色关系与长篇剧情。

建议只确立三个基础信息：

1. 玩家身处一个可以读取物理量的异常世界。
2. 玩家能够修改部分物体的物理量。
3. 随着探索深入，玩家会发现物理规则之间存在比表面现象更复杂的联系。

具体的世界起源、主线结局和角色设定可在核心玩法验证后继续扩展。

# 三、核心玩法系统

## 3.1 核心玩法循环

游戏的基本循环如下：

**观察环境 → 识别障碍 → 分析物理关系 → 选择目标物体 → 修改物理量 → 观察结果 → 组合其他物体 → 达成目标**

每个关卡都应让玩家完成至少一次有意义的推理。

例如，玩家面对一道较高的平台：

1. 观察发现附近存在一块可移动的石头。
2. 查看石头属性，发现其质量较大。
3. 将石头质量降低，使其更容易被推动。
4. 将石头移动到合适位置。
5. 修改其弹性参数，使其能够提供较强的反弹。
6. 利用石头跳到高处的平台。

这个例子是用于说明设计方向的组合谜题，不代表最终关卡已经确定。

## 3.2 玩家能力

建议首发版本包含以下能力。

### A. 物体观察

玩家可以观察场景中的物体，并查看其可修改属性。

展示内容包括：

- 物体名称。
- 当前数值与单位。
- 当前物理状态。
- 可修改的物理量。
- 与当前谜题相关的提示信息。

不是所有物体都必须开放全部属性。物体的可修改范围由设计者定义。

### B. 物理量修改

玩家选中物体后，可以选择一个允许修改的物理量，并设置目标数值。

例如：

- 质量：10 kg → 2 kg。
- 温度：20 ℃ → 150 ℃。
- 体积：1 m³ → 0.1 m³。
- 恢复系数：0.2 → 0.9。

其中，质量、温度和体积属于有明确物理单位的物理量；恢复系数属于无量纲参数。后者可以纳入游戏的扩展编辑系统，但应与严格意义上的单位修改区分。

### C. 环境实验

修改完成后，游戏应及时更新相关物理表现。

例如：

- 质量变化影响物体的惯性和重力相关行为。
- 温度变化影响热传递、融化或热机关。
- 弹性参数变化影响碰撞反弹和形变。
- 光学参数变化影响光线传播或传感器响应。

### D. 组合操作

玩家可以连续修改多个物体，建立相互依赖的解谜链。

例如：

高温热源 → 加热液体 → 产生蒸汽 → 推动装置 → 打开通道。

组合效果必须遵循清晰规则。若某条链路尚未在游戏中实现，就不能仅因为现实中存在这种现象而默认它可用。

# 四、物理量与单位系统

## 4.1 基本设计原则

本作采用“物理量驱动玩法”的设计方式。

物理量并非装饰性标签，而是控制物体行为的参数。单位用于表达物理量的种类和数量级。

系统需要区分三类修改：

| 类型 | 示例 | 游戏含义 |
|---|---|---|
| 数值修改 | 10 kg → 2 kg | 改变同一种物理量的大小 |
| 单位表示切换 | 100 cm → 1 m | 等价表达，不改变实际物理状态 |
| 跨物理量重写 | 10 kg → 100 ℃ | 改变属性类型，属于游戏规则，不是现实单位换算 |

其中，第三类是游戏最有辨识度的概念，但也最容易产生理解混乱。

建议在首发版本中，将跨物理量重写作为一种特殊的“属性重写”能力：玩家选择目标属性，系统根据该物体允许的规则，将其转换为新的状态。

**不要把 `10 kg → 100 ℃` 解释为现实中的换算。** 质量与温度是不同维度的物理量，二者不存在这样的单位换算关系。

## 4.2 物理量修改模式

建议系统同时支持两种模式。

### 模式一：同类参数编辑

物体保持原有物理量类别，只改变数值。

示例：

- 质量：10 kg → 2 kg。
- 温度：20 ℃ → 150 ℃。
- 恢复系数：0.2 → 0.9。

优点是直观、容易推理，适合作为教学和基础关卡的核心。

### 模式二：属性类型重写

物体的某个属性被替换为另一种属性，物体获得新的行为。

例如，原本不能发光的物体被赋予光源属性，或某个装置被赋予电压，成为电路中的电源。

这类效果必须通过明确的转换规则定义，不能仅仅更改一个单位字符串后就假设物体具备对应功能。

建议在原型阶段只开放少数几种跨类型重写，并对每一种都制定严格的输入、输出与状态转换规则。

## 4.3 首发版本物理量清单

建议首发原型重点验证以下物理量。

| 物理量 | 单位示例 | 主要玩法作用 | 优先级 |
|---|---|---|---|
| 质量 | kg | 惯性、受力响应、搬运与推动 | P0 |
| 长度 | m | 尺寸、距离、伸缩机关 | P1 |
| 体积 | m³ | 容量、容纳、空间限制 | P1 |
| 温度 | ℃、K | 热源、热传递、温度门槛 | P0 |
| 力 | N | 推动、拉动、弹射 | P1 |
| 时间 | s | 延迟、持续时间、计时机关 | P1 |
| 光通量 | lm | 光源亮度表现、光敏机关 | P2 |
| 电压 | V | 电路供能 | P2 |
| 电阻 | Ω | 电路响应与电流控制 | P2 |
| 压强 | Pa | 压力门、液体与气体机制 | P2 |
| 流量 | m³/s | 液体输送、管道谜题 | P2 |
| 杨氏模量 | Pa | 材料拉伸与压缩的软硬程度 | P1 |
| 恢复系数 | 无量纲 | 碰撞后的反弹能力 | P0 |
| 阻尼系数 | 依模型而定 | 振动衰减与回弹稳定性 | P2 |

优先级说明：

- **P0：** 最早用于验证核心玩法。
- **P1：** 核心玩法成立后加入。
- **P2：** 扩展阶段加入，前提是有足够的关卡需求。

首发版本不建议同时实现所有物理量。每增加一种物理量，都意味着新增规则、UI 展示、状态处理、测试和关卡组合成本。

## 4.4 物理量的可修改范围

每个物体都应拥有独立的属性配置。

例如：

- 普通石块：质量、恢复系数。
- 金属平台：质量、温度、热传导属性。
- 热源装置：温度、热功率。
- 灯具：光通量。
- 电力装置：电压、电阻或指定电路属性。

这样可以避免玩家修改一个普通石头的所有物理量，从而产生难以控制的复杂情况。

物体是否允许修改某个属性，应由物体配置决定，而不是完全由全局规则决定。

# 五、弹性与碰撞系统

## 5.1 设计目标

弹性系统是 UNITSHIFT 的一个重要扩展方向。

玩家可以让普通物体表现出不同的软硬程度、形变能力和碰撞反弹效果。例如，一块石头可以变得像橡胶球一样弹跳，或者像史莱姆一样压缩、回弹。

但需要注意：现实中的“弹性”并不是一个能够完整描述所有行为的单一物理量。因此，游戏中应将软硬、反弹和振动衰减分开设计。

## 5.2 核心参数

### 恢复系数

恢复系数通常记为 \(e\)，是一个无量纲参数。

它描述理想化碰撞中，碰撞后与碰撞前相对速度的关系。

- 接近 0：碰撞后几乎不反弹。
- 中等数值：具有一定反弹能力。
- 接近 1：理想化情况下具有较强反弹能力。

建议在游戏中使用 0～1 的范围作为首版基础规则。

### 杨氏模量

杨氏模量的单位为 Pa，用于描述材料抵抗拉伸或压缩形变的能力。

- 较高：材料更难发生形变。
- 较低：材料更容易发生形变。

但杨氏模量本身不能完整决定碰撞后的反弹高度。反弹效果还受到恢复系数、形状、碰撞速度和阻尼等因素影响。

### 阻尼

阻尼用于描述振动或形变过程中的能量消散。

- 阻尼较低：形变后可能持续振动。
- 阻尼较高：形变更快稳定。

## 5.3 首版简化方案

为了避免早期开发陷入复杂的软体物理模拟，建议先实现：

1. 恢复系数：控制碰撞反弹强度。
2. 形变程度：游戏抽象参数，控制物体受压时的视觉压缩量。
3. 形变恢复速度：控制物体恢复原状的速度。

其中，后两项是游戏参数，不必声称它们完全等同于真实材料常数。

首版可以使用刚体碰撞加动画形变实现视觉效果，不需要立刻开发完整的软体物理求解器。

## 5.4 关卡用途

- **弹跳平台：** 通过修改恢复系数获得足够的跳跃高度。
- **弹性石块：** 将普通石块变成可以反弹的跳板。
- **缓冲装置：** 利用低反弹材料吸收冲击，避免机关被撞坏。
- **压缩弹射：** 物体受压后储存弹性势能，并在释放时推动其他物体。
- **软硬通道：** 通过改变形变能力，使物体通过狭窄区域。

这些玩法应逐步验证。尤其是压缩弹射与软体挤压，需要在原型中确认物理实现成本，再决定是否进入首发版本。

# 六、物体交互与物理规则

## 6.1 物体状态

每个可交互物体建议具有以下状态：

- 正常状态。
- 已被选中。
- 正在修改。
- 属性修改完成。
- 发生物理交互。
- 暂时失效或被机关锁定。
- 处于特殊状态，例如加热、通电、融化或形变。

状态之间的切换必须有明确条件，避免多个机制同时作用时产生不稳定行为。

## 6.2 物理交互规则

建议将物理交互分为以下类别。

### 机械交互

包括碰撞、推动、承载、弹跳、拉动和阻挡。

### 热学交互

包括热量传递、温度变化、加热触发和冷却条件。

### 电学交互

包括供电、电路连通、电阻影响和电力机关。

### 光学交互

包括照明、遮挡、光敏触发和光线传播。

### 流体交互

包括液体流动、容器容量、流量和压力作用。

这些交互类别并不意味着首发版本全部实现。它们是后续可扩展的系统边界。

## 6.3 物理模拟与解谜抽象

游戏不必严格模拟所有现实物理现象。

例如，玩家将某个物体的温度提高到设定阈值时，可以触发加热机关；不必模拟完整的微观热传导过程。

但抽象必须保持一致：

- 相同物体在相同条件下应产生一致结果。
- 物理阈值必须可以被观察或推断。
- 物体状态变化必须有清晰反馈。
- 如果某种现实效果被简化，游戏内的其他同类情境也应遵守相同规则。

# 七、关卡设计

## 7.1 关卡设计目标

关卡不是单纯让玩家寻找可以修改的物体，而是让玩家通过修改物理量理解一种规律，并在后续关卡中组合规律。

每个关卡应至少满足以下条件：

1. 存在明确的通关目标。
2. 关键物体与机关之间存在可理解的关系。
3. 玩家能够通过观察发现线索。
4. 玩家失败后能够知道失败的原因。
5. 解法依赖物理规则，而不是依赖隐藏的随机事件。

## 7.2 关卡教学结构

建议采用以下学习曲线。

| 阶段 | 目标 | 关卡设计方式 |
|---|---|---|
| 第一阶段：认识 | 理解查看和修改属性 | 单一物体、单一变化 |
| 第二阶段：验证 | 理解某个参数的效果 | 修改前后对比 |
| 第三阶段：应用 | 将参数用于明确目标 | 单一机制解决障碍 |
| 第四阶段：组合 | 同时利用两种物理关系 | 两个以上的交互环节 |
| 第五阶段：推理 | 通过环境线索自行提出方案 | 减少直接提示 |
| 第六阶段：实验 | 允许多种可行解 | 提供开放式目标 |

## 7.3 示例关卡

以下是用于验证设计方向的关卡草案。

### 关卡 A：质量

**目标：** 将石块移动到指定位置。

场景中存在一个较重的石块和一条狭窄通道。

玩家可以查看石块质量，并降低其质量，使其更容易被推动。

本关重点：理解质量修改与移动行为之间的关系。

### 关卡 B：弹性

**目标：** 利用石块跳上高处平台。

玩家需要调整石块的恢复系数，使其在受到碰撞时产生足够的反弹。

本关重点：理解反弹参数与跳跃高度之间的关系。

### 关卡 C：温度

**目标：** 启动热敏机关。

场景中存在一个需要达到指定温度才能激活的装置。玩家需要找到合适的热源，并调整其温度。

本关重点：理解温度阈值和机关状态之间的关系。

### 关卡 D：机械与热学组合

**目标：** 打开被锁住的通道。

玩家需要先利用热源改变某个物体的状态，再利用改变后的物体推动或触发机械机关。

本关重点：让不同物理机制构成因果链。

### 关卡 E：电学

**目标：** 恢复电路并打开出口。

玩家需要利用电源、电阻和导电路径，让电路满足机关的触发条件。

本关重点：在基础系统成熟后引入新的物理交互类别。

## 7.4 多解设计原则

并非所有关卡都需要多解，但开放式关卡可以鼓励玩家创造不同方案。

例如，同一个高处平台可以通过：

- 使用弹性物体弹跳。
- 调整物体质量后推动箱体。
- 使用某种机械装置改变平台位置。

只要解法符合系统规则，并且不会破坏后续流程，就可以视为有效解法。

对重要关卡应进行“非预期解法测试”，避免玩家利用某个过强的物理参数跳过大量内容。

---

# 八、操作方式与交互界面

## 8.1 基础操作建议

PC 版本建议采用鼠标与键盘操作。

| 操作 | 建议功能 |
|---|---|
| 鼠标左键 | 选择或交互 |
| 鼠标悬停 | 显示物体信息 |
| 鼠标右键 / Esc | 取消选择或退出编辑 |
| WASD / 方向键 | 控制角色移动 |
| 空格键 | 跳跃或执行上下文动作 |
| Tab | 打开物体属性面板 |
| 滚轮 | 调整数值或切换属性 |
| Enter | 确认修改 |

实际按键应在原型阶段验证，避免与数值输入、角色控制或镜头操作冲突。

## 8.2 物体信息界面

选择物体后，界面显示：

- 物体名称。
- 当前可修改的物理量。
- 数值和单位。
- 物体当前状态。
- 与当前属性有关的简短说明。

例如：

**石块**

质量：10 kg  
恢复系数：0.2  
状态：静止

## 8.3 属性编辑界面

属性面板应允许玩家：

1. 选择物理量。
2. 输入目标数值。
3. 查看单位。
4. 确认修改。
5. 观察修改后的结果。

建议对高风险或影响较大的修改提供预览。例如，修改后物体会明显变轻、发热或产生高反弹时，界面可以提示对应效果。

## 8.4 信息反馈

每次修改都应具有视觉或音效反馈。

建议包括：

- 被修改物体短暂高亮。
- 数值变化动画。
- 物体材质或特效变化。
- 物理状态变化提示。
- 修改成功或失败的简短提示。

反馈应帮助玩家理解因果关系，而不只是追求视觉效果。

# 九、美术与视觉表现

## 9.1 视觉定位

建议采用 2.5D 视觉方案：

- 使用 3D 模型呈现角色、物体和环境。
- 采用固定或受控的正交相机。
- 以二维侧视玩法为基础。
- 限制主要解谜对象的运动维度。
- 通过材质、光照和特效突出物理属性变化。

这种方案兼顾了二维解谜的可读性和三维场景的表现力。

## 9.2 场景风格

建议优先采用简洁、结构清楚的实验空间，而不是一开始就制作大规模写实世界。

场景应具备：

- 清晰的前景、中景和背景。
- 容易识别的可交互物体。
- 明确的机关边界。
- 能够提示物理关系的视觉元素。
- 足够的留白，避免信息过载。

## 9.3 物理量的视觉语言

不同物理量需要具有稳定的视觉表达。

| 物理属性 | 表现建议 |
|---|---|
| 质量 | 可通过重量标识、移动反馈和受力表现体现 |
| 温度 | 热浪、颜色渐变、蒸汽等 |
| 弹性 | 压缩、拉伸、回弹动画 |
| 电学 | 电弧、导线发光、电流流动效果 |
| 光学 | 光束、照明范围、遮挡变化 |
| 流体 | 液面、流动轨迹、容器变化 |

颜色不能成为唯一识别手段。应结合图标、文字、动画和音效，以提升可读性。

## 9.4 模型制作原则

- 优先制作可重复使用的模块化模型。
- 机关与装饰物分开管理。
- 物理碰撞体尽量保持简单。
- 视觉模型不必与碰撞模型完全一致。
- 对关键物体使用统一的高亮和选中反馈。

---

# 十、音效与音乐

## 10.1 音效目标

音效应当帮助玩家理解物体状态，而不是单纯增加氛围。

建议优先制作：

- 物体被选中的提示音。
- 属性修改成功音。
- 物体碰撞和反弹音。
- 加热、冷却和融化音效。
- 电路接通与断开音效。
- 机关激活和关卡完成音效。

## 10.2 音乐方向

建议以轻度科幻、实验室氛围和简洁电子音乐为主。

解谜时的音乐应避免过强节奏，以免干扰玩家思考。随着关卡推进，可以逐渐增加音乐层次，强化玩家理解世界规则后的探索感。

---

## 11.5 物理量数据与游戏参数

建议将属性分为两类：

**真实物理量：** 质量、温度、长度、电压等，使用明确的单位。

**游戏抽象参数：** 形变程度、交互优先级、机关灵敏度等，不一定对应单一真实物理量。

恢复系数虽然有明确的物理含义，但它是无量纲参数，不属于有单位的物理量。

系统应当明确区分这些类别，以便后续扩展和维护。

## 11.6 关卡重置与状态管理

玩家需要能够快速重置当前关卡。

重置时应恢复：

- 物体初始属性。
- 物体初始位置。
- 机关初始状态。
- 已触发的临时效果。
- 关卡内的临时连接关系。

如果存在跨关卡进度，则需要将其与关卡内的临时状态分开管理。


# 十七、后续扩展方向

以下方向可以在核心玩法稳定后评估。

## 17.1 更多物理量

- 电压、电流、电阻。
- 压强与流量。
- 光通量与光敏机关。
- 频率与振动。
- 材料弹性与阻尼。

每种新物理量都应以实际关卡需求为依据，不以数量作为内容丰富度的唯一标准。

## 17.2 属性组合

更有潜力的扩展不是单纯增加属性，而是建立新的交互链：

- 温度与材料状态。
- 质量与惯性。
- 弹性与碰撞。
- 电压与电路连通。
- 光照与传感器。
- 压强与流体运动。

## 17.3 玩家创作内容

如果游戏的物理规则足够稳定，可以考虑开发关卡编辑器，让玩家组合物体、设置属性与设计目标。

这会增加长期可玩性，但同时需要投入编辑器 UI、关卡校验、内容分享和兼容性维护，因此应在核心产品验证后再决定。

---

# 十八、最终设计原则

UNITSHIFT 的长期方向应围绕以下原则展开：

1. 物理量是游戏规则的入口，而不是装饰性的文字标签。
2. 每一种修改都应该产生可理解、可验证的后果。
3. 物理量之间的组合比物理量数量本身更重要。
4. 游戏可以抽象现实，但不能随意改变已经建立的规则。
5. 关卡应鼓励观察、实验、推理与创造。
6. 技术实现优先服务于玩法验证，不为尚未证明有价值的复杂模拟付出过高成本。
7. 新机制只有在能带来新的解谜空间时，才值得进入首发版本。

## 项目总结

UNITSHIFT 希望建立一种以物理量为语言、以规则修改为工具、以实验推理为核心的解谜体验。

玩家不是简单地寻找钥匙来打开门，而是理解物体为什么会以某种方式行动，再通过修改它的属性，让世界产生新的可能。

**在 UNITSHIFT 中，玩家不只是利用世界的规则，而是尝试重新定义规则。**
