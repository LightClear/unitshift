# Godot 工程指南

适用于引擎配置、场景、资源、UI、导入和插件。遵循[根规则](../../AGENTS.md)与[项目上下文](project-context.md)。

## 环境与工具

核实实际 Godot 构建、对应导出模板和项目兼容性；第一方脚本统一使用 GDScript。
声明版本不等于脚本能够解析、场景能够加载或游戏能够运行。
优先检查本地项目和版本信息；不确定的 API 查匹配版本的官方资料。
MCP／编辑器插件只在实际支持的文件和操作范围内使用，不假定覆盖所有 GDScript 与场景测试。
不因局部任务自动升级引擎、换渲染器、装插件或改全局编辑器设置。

## 生命周期与架构

明确每个场景和服务的创建者、所有者、释放时机与接口；使用项目已有组装方式，不强制特定根类名。
场景和节点适合生命周期与呈现，独立规则避免依赖无关 UI；需要脱离场景树的逻辑可用 RefCounted，拆分按项目需求决定。
依赖显式传入；本地节点引用可使用适合的绑定方式，不以深层场景位置作为核心业务身份。
退出／替换场景时清理订阅和演出任务，持久游戏状态不能意外随临时界面释放。
Autoload 与事件总线需有明确生命周期和边界；避免全局万能管理器，也不一概禁止引擎原生能力。

## Resource 与持久数据

- 区分共享配置和可变实例，检查复制深度与集合别名，防止多个实例互相污染。
- 配置、内容引用和运行时状态沿用实际管线，不强制所有项目拥有 Catalog 或 Resource 投影层。
- 改持久字段前核对兼容、默认值、迁移和损坏处理。
- 移动文件时同步脚本绑定、场景、Resource、UID 及脚本路径引用；重新扫描后加载实际场景。
- 源码目录与资源目录可按项目需要分离或就近组织，不由模板决定。
- 不直接修改 .godot 缓存作为正式修复，保留必要源资源与导入配置。

## UI、输入与呈现

沿用项目的 Control／Container、Theme、锚点和窗口缩放方案，不强制固定分辨率或 stretch 设置。
UI 表达数据与用户请求，核心规则由明确的所有者处理；命中区域与视觉效果分别检查。
按已支持设备检查鼠标、键盘、手柄或触摸，避免未经授权扩展平台；模态退出恢复合理焦点。
动态文字和数值使用真实文本控件，颜色不是关键状态唯一提示；检查长文本和不同窗口比例。
玩法相关动画明确取消、跳过、切屏和重新绑定语义，不重复触发伤害、支付或奖励。
美术导入来源与确认版本遵循[美术指南](art-guide.md)。

## 验证

GDScript 绑定、class_name 或导出属性修改后先确认解析并刷新，再检查 Inspector／MCP；不要以旧显示断言新代码无效。
工具创建场景后检查实际节点、资源引用和连接，再运行适用场景。
验证进程与用户其他运行实例隔离，不随意结束无关程序。
导出检查脚本、资源、字体、插件依赖、开发入口和目标平台运行；按[测试指南](testing-guide.md)报告实际层级。
