# GDScript 编码规范

本项目的第一方脚本统一使用 GDScript，包括玩法、UI、工具和测试脚本。
遵循[根规则](../../AGENTS.md)与[项目上下文](project-context.md)；第三方插件和生成代码保留原有边界，不自动按本规范改写。
语言特性和 API 以项目实际使用的 Godot 版本为准；配置声明不能代替解析、加载和运行验证。

## 通用原则

- 按职责组织类型和方法，不按机械行数拆分；接口服务于真实边界。
- 显式传入依赖，避免隐蔽静态状态、深层场景查找和重复服务实例。
- 区分无副作用查询与状态操作，说明输入验证、失败和恢复语义。
- 内容配置不散落到代码特例中；稳定 ID 与展示名称分开维护。
- 变更公开接口前搜索调用方，同步场景、资源、序列化和测试。
- 不吞错、不返回伪成功；日志提供必要上下文，不泄漏敏感信息或无节制刷屏。
- 优化需有测量或明确约束；依赖和抽象必须服务当前需求。

## 命名与可见性约定

命名遵循 [Godot 官方风格指南](https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/gdscript_styleguide.html)，并采用以下项目约定：

| 对象 | 约定与示例 |
| --- | --- |
| 脚本文件与新目录 | snake_case，如 `selection_state.gd`；文件名与主要类型对应 |
| 类、`class_name`、内部类与具名枚举 | PascalCase，如 `SelectionState`、`SelectionMode` |
| 场景节点 | PascalCase，如 `SelectionPanel`；沿用引擎类型中的数字与缩写 |
| 函数、变量、参数与属性 | snake_case，如 `select_item()`、`selected_id` |
| 内部函数与成员 | 单下划线前缀，如 `_refresh_view()`、`_selected_id` |
| 信号 | snake_case；已发生事件用 `selection_changed`，请求用 `selection_requested`，语义应区分 |
| 普通常量与枚举项 | UPPER_SNAKE_CASE，如 `DEFAULT_MODE`、`SINGLE` |
| 预加载的脚本类型常量 | 作为类型使用时用 PascalCase，如 `const SelectionState = preload("res://实际路径/selection_state.gd")`；路径仅为示意 |

- 下划线表达内部使用约定，不构成语言级访问控制；跨脚本只依赖明确的公开接口。
- 只为需要复用或类型标注的稳定类型声明 `class_name`，避免与内置类、其他全局类和 Autoload 名称冲突。
- 保留引擎回调的原始名称和签名，如 `_ready()`、`_physics_process(delta: float) -> void`；不用非虚原生方法名伪装重写。
- 名称表达职责与单位；避免含混缩写、无意义类型前缀，以及遮蔽内置成员或外层变量。
- 导出属性、信号、资源字段和枚举持久值的改名或重排先查引用与存档兼容，不按命名规范机械批量改动。

## 目录、脚本组织与格式

源码沿用项目实际目录，不因模板创建平行根目录。移动脚本时同步场景绑定、资源引用和 UID，不保留新旧重复实现兜底。

- 脚本按职责组织；纯规则或临时逻辑对象可用 `RefCounted`，可编辑和序列化配置用 `Resource`，需要场景树生命周期或呈现时用 `Node` 及其子类。
- 优先组合与小接口，不为复用少量代码建立深继承；继承自定义基类时确认初始化和清理是否需要调用 `super`。
- 默认排列：工具注解（如需）→ `class_name`（如需）→ `extends` → 类文档 → 信号 → 枚举 → 常量 → 静态成员（如需）→ 导出属性 → 普通成员 → `@onready` 成员 → 初始化与引擎回调 → 公开方法 → 内部方法 → 内部类。
- 同组内公开成员在前、内部成员在后；局部变量靠近首次使用声明，不把局部临时值提升为成员。
- 使用 UTF-8 无 BOM、LF、末尾一个换行，无行尾空格；GDScript 使用 Tab 缩进，每个代码块一级，不混用空格缩进。
- 每行一条语句，不用分号拼接；分支、循环和函数体正常换行，不以单行写法压缩业务流程。
- 顶层函数之间通常留两个空行，函数内按流程阶段留一个空行；内部类方法之间留一个空行。
- 行宽以约 100 字符为阅读目标；参数和条件用括号隐式续行，通常比所在语句多缩进两级，数组、字典和枚举内容多一级；多行集合项保留尾逗号。
- 运算符两侧、逗号后加空格；不以空格纵向对齐赋值。优先使用 `and`、`or`、`not`，条件不加多余括号。
- 字符串默认双引号；单引号能明显减少转义时可用。避免嵌套条件表达式隐藏业务分支。

格式工具只处理明确选中的第一方文件，先核实已有 `.editorconfig` 和工具配置，不自动引入新格式器或修改全局编辑器设置。
核对实际检查文件数量；零文件不能证明格式通过。格式器不能代替命名、注释和行为审查。

## 静态类型与数据边界

默认采用有类型的 GDScript，细节参照[官方静态类型说明](https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/static_typing.html)。

- 成员、导出属性、函数参数、返回值和信号参数明确类型；无返回值写 `-> void`，如 `signal selection_changed(item_id: StringName)`。
- 局部变量在右侧类型清晰时可用 `:=`，如 `var offset := Vector2.ZERO`；数值单位、空值、基类接口或返回类型不明显时显式标注。
- 避免把 `Variant` 结果直接交给 `:=`；动态值先用显式 `Variant` 接住，在边界校验后进入有类型的内部逻辑。
- 同类集合标注元素或键值类型，如 `Array[Node2D]`、`Dictionary[StringName, int]`；多层结构优先具名数据类型，不写引擎不支持的嵌套泛型集合。
- JSON、存档、插件回包和动态属性读取需校验键、类型、必需值与业务范围；不能把缺失、空值和合法的零值混为一谈。
- `is` 用于检查类型；对象 `as` 转换可能得到 `null`，使用前按契约处理失败，不能把强制转换当输入验证。
- 对可能已释放的对象使用 `is_instance_valid()`，按流程需要检查 `is_queued_for_deletion()`；只判断 `!= null` 不能证明对象仍有效。
- 枚举表达封闭状态集；序列化依赖枚举值时使用明确稳定值。稳定标识可用 `StringName`，展示文本使用 `String`；显示名称不能充当持久身份，类型本身也不保证 ID 稳定。

## 节点绑定、导出与生命周期

生命周期依据 [Node 文档](https://docs.godotengine.org/en/4.7/classes/class_node.html)，导出字段依据[官方导出属性说明](https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/gdscript_exports.html)。

- 必需场景依赖通过类型明确的 `@export`、初始化接口或场景内部绑定提供；初始化时检查缺失，不用悄悄新建服务掩盖装配错误。
- 场景内部固定节点用类型明确的 `@onready` 引用；`%UniqueName` 依赖实际设置及所属场景范围，不能当成全局查询。
- 可选节点可用 `get_node_or_null()` 并处理缺失；高频路径缓存节点引用，避免每帧重复查找或依赖跨场景的深层路径。
- `_init()` 不访问尚未就绪的子节点；需要由 `PackedScene.instantiate()` 创建或由编辑器构造的类型，不要求必填构造参数。
- 子节点 `_ready()` 先于父节点；父节点后续注入依赖时使用明确初始化入口，不能假定子节点在 `_ready()` 已取得这些依赖。
- `_enter_tree()`／`_exit_tree()` 可能多次执行，处理重复进入、退出与重绑；`_ready()` 默认不会在每次重新入树时重跑，不把它当每次显示的初始化入口。
- 不在同一字段上同时使用 `@export` 与 `@onready`；属性 setter 可能在就绪前执行，数据校验与依赖节点的刷新分开处理。
- `@export_range`、`@export_enum`、`@export_group` 等只在有实际编辑需求时使用；Inspector 提示不替代运行时校验，不擅自新增玩法范围。
- 物理相关逻辑使用 `_physics_process()`，帧相关呈现使用 `_process()`；时间量明确单位，按 API 约定使用 `delta`，避免重复乘入时间步长。
- 只有确需编辑器执行时才添加 `@tool`，用 `Engine.is_editor_hint()` 区分编辑器行为，防止误写运行存档或自动触发业务副作用。

## 信号、Callable 与异步流程

信号连接参考 [Object 文档](https://docs.godotengine.org/en/4.7/classes/class_object.html)，`await` 语义参考 [GDScript 语言参考](https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/gdscript_basics.html#awaiting-signals-or-coroutines)。

- 优先 `source.changed.connect(_on_changed)` 和 `changed.emit(...)`；仅在信号名确实动态时使用字符串接口，并检查存在性与连接结果。
- 编辑器连接与代码连接选清楚的单一入口；可重复绑定时用 `is_connected()` 或显式解绑，避免同一通知重复执行。
- 连接生命周期与业务订阅范围一致；退出场景、切换数据源或关闭临时功能时按需解绑。对象释放会移除相应连接，但退出场景树不等于对象释放。
- 需要解绑的 lambda、`bind()` 结果保留对应 `Callable`，不要重新构造回调来解绑；闭包捕获的对象和数据有明确有效期。
- 父级通过公开接口组织子对象，子对象用信号通知变化或请求；跨系统采用已有装配方式，不为每个信号创建全局总线。
- 需要结果的协程由调用方 `await`；不等待的调用必须有明确所有者、错误出口和收尾方式，不能用无人负责的后台流程承载关键结算。
- 每个等待点都考虑重入、场景切换和对象释放；恢复后检查操作是否仍有效，按需使用忙碌状态或操作序号。取消时主动收尾，不能假定等待的信号一定会再次发出。
- 不在每帧回调中无保护地启动协程；延迟调用用于正确时序，不用任意等待帧数掩盖初始化依赖。
- Tween、Timer 和动画由明确对象持有和清理；根据生命周期选择 `Node.create_tween()`、绑定节点或显式停止，不因演出取消、跳过或回调重复而重复结算。

## 集合、Resource 与对象所有权

资源共享与复制以 [Resource 文档](https://docs.godotengine.org/en/4.7/classes/class_resource.html)和实际对象图为依据。

- `Array`、`Dictionary` 的赋值与传参会共享容器；公开接口说明是否允许调用方修改，返回内部集合不能冒充只读快照。
- 复制时检查容器、嵌套容器和 `Resource`／对象元素各自的共享关系；`duplicate()`、深复制参数和 Local to Scene 都不等于任意对象图完全独立。
- 共享 `Resource` 用作配置时不承载各实例的可变状态；需要独立状态时分离状态对象或按实际版本复制，不能一律复制所有配置。
- 自定义可变 `Resource` 的公开修改入口按需要调用 `emit_changed()`，并明确通知时机；不假定普通成员赋值必然发送变更通知。
- 不在遍历字典时增删键；需要增删时遍历键快照或分阶段执行。数组遍历中移除元素需采用不会跳项的方式。
- 固定且适合随脚本加载的资源可用 `preload()`；动态路径使用 `load()` 或实际加载管线并检查结果。大资源和热路径按测量选择异步加载，避免反复同步读取。
- `Node` 由明确所有者负责释放，移出场景树不等于销毁；独立创建且未入树的节点也要处理。`RefCounted` 注意循环引用，不把节点引用当成可持久化 ID。

## 错误处理、数值与警告

- 检查返回 `Error` 的文件、资源或其他引擎操作；返回空值、布尔值或结果对象时说明其含义，不记录错误后继续宣称成功。
- `assert()` 只用于开发期不变量，不承担发布版必需校验；断言表达式不能包含业务副作用，参见[官方断言说明](https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/gdscript_basics.html#assert-keyword)。
- 明确整数除法、浮点转换、截断与舍入意图；浮点近似比较根据业务精度选择合适方法，不能用任意误差值改变玩法规则。
- 修复本次引入的解析错误和相关警告；`@warning_ignore` 只在具体位置有可说明理由时使用，不全局屏蔽警告来取得表面通过。
- 未使用的回调参数按约定加下划线；删除无职责的空回调。临时日志及时清理，不在逐帧循环中无节制输出。

## 中文注释覆盖

默认代码注释、文档注释、TODO／FIXME／HACK 正文用简体中文。API、协议字段和必要引用保留原文。
技术文档采用英文时，也不自动改变代码注释语言。已有用户约定优先。
类和公开成员使用 GDScript 的 `##` 文档注释，普通实现说明使用 `#`，标记后留空格；类文档放在 `extends` 后，成员文档紧邻声明之前。
类型、方法与属性引用采用 Godot 支持的文档标记，参见[官方文档注释说明](https://docs.godotengine.org/en/4.7/tutorials/scripting/gdscript/gdscript_documentation_comments.html)。

| 位置 | 应说明的信息 |
| --- | --- |
| 第一方脚本、类与枚举 | 职责、关键依赖与所有权；状态谁可改、生命周期与初始化前提 |
| 公开方法与信号 | 参数含义、单位、范围、空值约定、返回值、错误与副作用；信号触发时机、数据是否已经更新 |
| 非平凡内部方法 | 用途、算法步骤或不变量，不能因下划线前缀省略关键解释 |
| 导出属性、状态成员、数据对象、常量与枚举项 | 业务含义、默认值、边界和序列化映射；相近计数器与标记需区分 |
| 复杂流程块 | 校验、准备、执行、保存或发布等步骤的目的与时序 |
| 易错行为 | 集合与资源共享、信号解绑、等待与取消、随机数、失败恢复和旧版本兼容等原因 |
| 测试 | 场景、关键输入、断言目的与非直观边界，准备／执行／断言分组清楚 |

显然动作不用逐行翻译，但不能以代码自解释为由省略契约和边界；注释与逻辑同次更新。
不能编造线程安全、无副作用或回滚保证，也不能用注释掩盖尚未实现行为。
旧注释在相关修改或专门治理时更新，不自动全仓翻译。生成代码不手改，第三方许可和注释保留。

## 修改后的检查

- 核对命名、类型、格式、中文注释和受影响调用方；场景信号、导出字段和资源引用一起检查。
- 脚本变更执行实际解析／加载及相关行为测试；绑定、生命周期或信号变化增加对应场景运行。
- 集合或资源状态变化检查实例隔离；异步变化检查重复触发、退出与取消，持久数据变化遵循相应兼容约定。
- 仅修改本规范时检查格式、链接与来源一致性，不把文档检查报告成解析、运行或玩法验证。
