# 子代理协作指南

准备委派工作或集成子代理结果时读取。遵循[根规则](../../AGENTS.md)及当前会话的工具与代理限制。
本指南规定允许委派时如何协作，不要求每个任务启动子代理，也不授权绕过会话限制。

## 使用条件

默认由一个代理完成。只有任务边界明确、存在可独立推进的工作，且并行收益大于沟通成本时才考虑委派。
适合独立调查、只读评审、不同文件范围的实现或素材检查；先后依赖明显的工作按顺序完成。
主代理应保留有价值的本地工作，不能为了形式上的并行把一个简单改动拆给多个代理。
高风险改动需要认真复核，但不强制以额外代理代替主代理审查；能力不可用时仍执行适用验证。

## 每份任务必须包含

| 字段 | 要求 |
| --- | --- |
| 目标 | 明确问题或可验收产物 |
| 来源 | 根规则、必读指南、相关设计路径与内容 ID |
| 权限 | 只读调查或允许编辑；具体可写文件／目录 |
| 边界 | 禁止触及的文件、排除的后续功能、需保持的合同 |
| 接口 | 输入、输出、所有权、依赖与集成位置 |
| 验收 | 应执行的检查、交付证据及报告格式 |

子代理继承相同约束和用户已授权范围；主代理不能授予自己没有的权限。
不要把所有设计无差别塞给子代理，也不能省略会影响其判断的来源优先级。

## 写入协调

- 同一文件同一时间只有一个写入者，默认按文件或模块划定互不重叠的范围。
- 共享合同、项目配置、公共类型和根规则由主代理集中维护，或指定明确顺序。
- 子代理遇到跨范围问题先报告，不顺手改接口、玩法、数值或其他代理的文件。
- 共享目录中的修改立即可见；不能通过重置或清理撤销其他代理工作。
- 使用独立工作树时先确认仓库和当前未提交文件可用性，不把未经提交的资料当成已同步。
- 新增递归委派需由主代理统一协调，防止重复工作和失控占用并发资源。
- 发现输入或接口过期时通知主代理，暂停受影响写入；主代理负责调整顺序或任务范围。

## 交付与集成

子代理报告已完成事项、修改文件、执行的验证及结果、发现的问题、未完成内容和限制。
评审优先只读，反馈应有具体位置、触发条件、影响和修复建议，不只写风格偏好。
主代理检查实际文件与差异，处理接口和来源冲突，并执行必要的集成验证。
不能因为子代理说“完成”就宣布通过，也不能以子代理未做为理由遗漏用户必需目标。
最终对用户提供一个协调后的结果；不把相互矛盾的代理报告直接拼接交付。
