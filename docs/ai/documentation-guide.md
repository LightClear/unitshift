# 文档维护指南

遵循[根规则](../../AGENTS.md)。适用于设计、计划、确认记录、协作规则和其他文档修改。

## 单一来源与位置

根 AGENTS.md 维护常驻约束，docs/ai 维护按需工作指南。
玩法、美术、技术设计、决策与长期计划沿用接入项目目录，通过[项目上下文](project-context.md)登记入口。
目录不存在时按实际需求创建，不要求建立完整空目录树；不复制第二套平衡表、接口合同或状态表。
专业设计定义系统行为，AI 指南定义工作方式；引用已有事实优先链接，避免大段重复。

## 语言和格式

默认中文沟通与指南，专业文档沿用项目已确认语言。一个规范只维护一份权威正文，不默认完整双语副本。
API、资源 ID 和现有文件名保持稳定，新文件命名与项目一致。
使用 UTF-8、清楚标题、相对链接和正确围栏；链接目标应实际存在。
确认与验证记录填写真实日期、来源和范围，不能凭版本号或文件时间推断批准。

## 同步与记录

玩法改变更新对应来源；接口、所有权、存档、随机数或生命周期改变时同步相关技术设计。
不改变合同的局部修复不必重写整份架构或新建决定文档。
重要决定说明背景、选择、理由、替代方案、影响及授权依据；未决不能写成已确认。
用户已经授权的改动直接落实并记录，不重复要求批准。
保留已确认素材与历史版本，新确认关联具体文件及范围；最新记录不能自动追认其他未评审内容。

## 状态与验收

区分草稿、采用基线、确认、实现、验证和历史记录；静态检查不等于运行，视觉确认不等于交互通过。
示例命令和计划目录标明前提，不能冒充本次执行证据。
交付时检查相对链接、字段和内容 ID、格式与编码、来源一致性、占位状态及最终差异。
文档检查结果只证明相应文档属性，不报告成游戏测试通过。
